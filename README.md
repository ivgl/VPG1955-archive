# ВПИ 1955 — закрытый архив исходных материалов

Этот приватный репозиторий хранит исходные заявки, материалы событий, судейские документы и апелляции по годам. Он **не является каноническим состоянием** кампании. Единственный источник утверждённого мирового состояния: приватный `ivgl/VPG1955-state@main` (HEAD → манифест → JSON).

## Структура

- `turns/1955/posts/originals/` — неизменённые тексты заявок игроков.
- `turns/1955/posts/index.json` — реестр, Discord ID/ссылки, SHA-256, источник и права доступа.
- `turns/1955/events/` — подготовленные тексты событий с отдельным статусом (не игровые эффекты).
- `turns/1955/verdicts/` — литературные вердикты после появления.
- `turns/1955/appeals/` — апелляции и материалы рассмотрения.
- `turns/1955/decisions/` — утверждения администратора и ссылки на решения.
- `proposals/BACKLOG.md` — единый административный реестр идей на будущие сезоны (QoL, автоматизация Discord, сайт, процессы), со статусами и зависимостями; записи не являются утверждением работ.
- `scripts/verify_turn_readiness.py` — read-only проверка целостности принятого архива, HEAD/манифеста и судейских ворот; техническая процедура в [`VPG1955-state/docs/turn_readiness_gate.md`](https://github.com/ivgl/VPG1955-state/blob/main/docs/turn_readiness_gate.md).
- `qol/PROPOSALS.md` — оставленный для старых ссылок указатель на общий реестр.

### Правила обработки

1. Оригиналы постов не редактировать; исправления сохранять отдельно, с ссылкой на оригинал.
2. Публикация файла **не означает** судейского решения, завершения проекта или принятия игровой дельты.
3. Секретные планы и индивидуальные события доступны только лицам с доступом к этому репозиторию. Права GitHub действуют на весь репозиторий, поэтому доступ нельзя автоматически делить по странам.
4. Ссылки на Discord предоставлены администратором; текст и автор сообщений не проверяются Discord API автоматически.
5. Не коммитить изменения канонических JSON сюда. Окончательный релиз — только `VPG1955-state` по `STATE_WORKFLOW.md`.

## Приём материалов по решению администратора (29.10.2026)

- **Посты игроков:** при фазе `RECEIVING` и передаче администратором новых постов **на фиксацию** сохранять неизменённый текст сразу в `turns/YYYY/posts/originals/`; добавить `intake_id`, ссылку на Discord (если есть), автора/страну, `actor_key`, SHA-256 и уровень секретности в `posts/index.json`. Не архивировать текст, присланный исключительно для редактирования или обсуждения, без команды фиксации.
- **Оригинальность:** переданные администратором в чат тексты/вложения принимаются как оригиналы для игрового судейства. Недоступность Discord API **не препятствует архивированию** и не требует сверки как дополнительного условия. Фактический источник передачи фиксируется честно, независимую проверку Discord не изображать.
- **Идентификаторы:** `intake_id` (например, `INTAKE-1955-URS-ZHU-01`) — ID архивной заявки; `actor_key` (`URS-ZHU`) — читаемый короткий идентификатор заявленного актора. Это не автоматическое присвоение канонического `actor_id` зарегистрированного участника. Отсутствующий `actor_id` не блокирует приём; полномочия проверяются перед вынесением вердикта.
- **Ивенты:** генерация или редактирование ИИ **не запускает автоматический коммит**. Сохранять только конкретный текст, отдельно переданный администратором на фиксацию. Указывать статус `DRAFT`, `ADMIN_APPROVED` или `PUBLISHED` на основании его сведений, дату/канал/адресатов/секретность (если известны). Архивировать все подтверждённо опубликованные события; не заменять отсутствующие тексты историческими догадками.
- **Гарантия:** фиксация подтверждена только после коммита GitHub, повторного чтения текста/реестра и проверки SHA-256. При сбое писать «получено, но не зафиксировано». Оригинал не перезаписывать, версии/исправления вести отдельно. Секретные записи не помещать в публичный GitHub и не предоставлять доступ к этому репозиторию игрокам разных стран без проверки полномочий.

**Судейство:** `LOCKED` формирует снимок индексов по отдельной команде администратора; архивные записи не являются вердиктами. Канонические дельты и следующий год публикуются только через `ivgl/VPG1955-state` согласно `STATE_WORKFLOW.md`.
